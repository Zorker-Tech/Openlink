# Agent composer parity implementation plan

**Goal:** Align OpenLink's composer and command behavior to the supplied desktop client, using Codex source for runtime semantics. Never equate a successful individual test with complete UX parity.

**Architecture:** Explicit actions, submenus, argument-taking prompts and reference insertion. Runtime capabilities determine availability, not interaction type. Root suggestions never enumerate arbitrary child resources. UI state must preserve draft, selection and composition boundaries.

**Tech Stack:** React/Next.js, current Agent Host/Worker protocols.
